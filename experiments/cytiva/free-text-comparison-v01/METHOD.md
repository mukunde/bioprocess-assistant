# Corrected EN/FR candidate: prospective paired comparison v01

The user explicitly requested this candidate freeze after the corrected runtime
and GR01-GR04 review were merged in PR #45. This is a new method checkpoint, not
an amendment to a historical S trial. P/G equivalence reviews remain pending and
are not silently approved or included here.

## Lock before authoring

The method lock pins the interpreter, bridge, contracts, shared structured engine,
schema/catalog/source adapter, transitive source/review policy inputs, comparator,
this protocol, dependency versions, Python, offline tokenizer asset and resource
limits. Active tests are excluded from immutable method dependencies. The method
lock is written before any new questions/forms/references are authored. Questions
are then drafted without running either arm or repairing the candidate.

There are twelve new bilingual semantic scenarios, two per declared family:
multi-task ownership; operating stage versus buffer preparation; negation and
restriction scope; facts and uncertainty; numeric roles; partial support/policy.
They yield 24 language observations and 48 arm executions, not 48 independent
questions. Include at least two real context ambiguities and two partial-support
requests. All proposed paired forms must express the same critical meaning as
their text. An unresolved owner without a faithful current form is excluded from
the paired denominator and would require a separate semantic challenge, not a
dummy task. No such semantic-only case is silently substituted here.

## Review and execution gate

All twelve actual human approvals must bind both language texts, both structured
forms, documentary/intent references, exact origins and retained reservations.
Preparation/schema checks cannot approve any pair. Default CLI behavior verifies
files only; it never constructs either runtime. `--run` requires a review file
and a new output directory and is reserved for a later explicit execution request.
The directory is created exclusively after all checks, preserving attempted and
partial runs; a second attempt refuses to overwrite it. Candidate changes require
a new named freeze. Cases consulted during repairs become development evidence.

Only the validated `{language,text}` goes to F0 and only its structured submission
goes to S. Neither arm sees case IDs, references, passages, gold fields or answers.
Application-generated request IDs are opaque. S and F0 have independent runtime
instances initialized from identical frozen inputs; there is no conversation,
result cache, fallback retrieval or online update. One core call per arm at most.
Order is FT01-FT12, EN then FR, S-first on odd scenario numbers and F0-first on even
numbers. Save every arm output, including errors, before any scoring.

## Scoring and invariants

Intent is compared to the human-reviewed structured meaning, independently of
context success: exact tasks/owners, items, slots, facts/roles, selector/stage order,
restrictions and uncertainty. A single consistent bijection permits arbitrary
task/item IDs; no sorting hides scheduler-order changes. Explanatory reason prose
is not supplied meaning. Decimal strings compare numerically only within the same
unit; original text and code-point spans remain available. An unsupported grammar
result does not pass merely because abstention is safe or a sibling has a source.

Documentary references require the reviewed unit states, diagnostics and complete
eligible bundles, never just source presence. Source bytes/provenance, bindings,
quarantine, atomic dependencies and six-root/2,048-serialized-token budgets are
checked per complete request. Original F0 context token counts are checked before
ID normalization. E118-I/E121-EQ remain excluded. A pressure absence is restricted
to the exact 25 eligible excerpts, never the whole manual.

All 24 observations and 12 bilingual pairs must pass intent and documentary gates;
errors, rejected records, blocked units and incomplete inventories remain counted.
An available sibling must not be suppressed. If S fails first, investigate shared
method/reference limitations before attributing the difference to interpretation.
There is no generated answer, scientific suitability judgment or deployment gate.
Times are descriptive, not p95/p99 estimates. External model/API cost is zero;
record CPU elapsed times and human review separately. F1 confirmed text is deferred.

## Validity limits

New wording and combinations are authored by the same assistant with knowledge of
the code and corpus. This is post-freeze prospective, source-aware diagnostic
evaluation, not blinded independent validation or new source approval. Do not
select only grammar-friendly phrases or discard anticipated failures. P/G and
prior IF cases are development material, not part of this new denominator.
