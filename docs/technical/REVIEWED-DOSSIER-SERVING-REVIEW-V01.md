## Recommended implementation choices to clarify together

- **RC1 — First release medium:** local versioned bundle registry and excerpt view,
  using existing dossier/review artifacts. Defer Neo4j schema and public publication
  until the handoff is demonstrated. Contract acceptance does not itself authorize
  graph writes or default activation.
- **RC2 — Reader experience:** show product, explored category, conditional options,
  attached warnings and scoped reservations first; make the full original excerpt
  and audit trail one click away. Do not require a model to explain missing fields.
- **RC3 — Withdrawal authority:** before a release, designate the human-reviewed
  versioned withdrawal/revocation inventory checked during startup/lookup. Preserve
  prior records; a changed authority creates a new release. Existing review
  verifiers do not implement a universal revocation feed.
- **RC4 — Publication and future selection:** implement a model-free local handoff
  first. Only after its release checks should a separate opt-in chat route be
  considered, with a tool schema and deterministic selector that cannot broaden
  admitted support. No paid call is needed to validate this first handoff.

## Evidence and review record boundary

All existing MS/C and Q/N human quotations, source facts and frozen records remain
unchanged. No new human decision has been recorded. After review, record the
user's exact message and its scope in a new decision artifact; never prefill
approval, silently modify the old decisions or promote a design choice to source
or operational approval.
